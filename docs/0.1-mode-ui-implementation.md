# Mode-oriented UI (0.1.0 candidate)

PRs #19–22 have been merged. This document describes the implemented first pass of File > New Buffer in Mode…, Change Buffer Mode…, mode-local R source and console menus, and R toolbar command maps.

## Design

- The File menu uses the existing Glassmacs document-opening policy and produces new untitled buffers.
- R execution actions reuse existing `glassmacs-r-send-*` / ESS commands; no second evaluation engine.
- R source and ESS console menus are distinct and depend on the active buffer.
- The toolbar command map is buffer-local, and the preference is `glassmacs-r-show-toolbar`; toolbar rendering, image availability, and per-window placement require real macOS GUI testing.
- PR #20 added image-backed toolbar entries; availability of image assets and the resulting Cocoa rendering remain unverified. If the toolbar does not render properly, inspect GNU Emacs toolbar image support and evaluate `window-tool-bar` before introducing custom Cocoa.

## Required GUI validation

1. Open File > New Buffer in Mode…, select R, confirm untitled R source mode and window policy.
2. Verify Change Buffer Mode… and that unsaved text is preserved.
3. In an R source buffer, inspect the R menu and run line, selection, function and buffer.
4. In the ESS R console, inspect the console-specific menu and interrupt/history.
5. Inspect the top toolbar; confirm visible and clickable controls in R buffers and absence of inappropriate controls elsewhere.
6. Verify toolbar operations use correct source buffer and explicit R session; verify console/history actions.
7. Change `glassmacs-r-show-toolbar` through Customize, restart and verify persistence.
8. Ensure no new data-loss or document/window lifecycle regressions.

## Known uncertainties

These are GitHub-authored source changes. No Emacs binary or macOS GUI is available in the assistant's environment, so ERT, byte-compilation, native toolbar rendering and menu presentation are **not verified**. Merge only after CI and a focused native UI acceptance pass.

## Integrated 0.1 development status — 2026-10-27

PRs [#18](https://github.com/jmping/Glassmacs/pull/18), [#19](https://github.com/jmping/Glassmacs/pull/19), [#20](https://github.com/jmping/Glassmacs/pull/20), [#21](https://github.com/jmping/Glassmacs/pull/21), and [#22](https://github.com/jmping/Glassmacs/pull/22) have merged into `main`. The most recent merge was #22 at `604e44e`. Their pull-request CI completed successfully (Emacs ERT, ESS/R integration, and macOS launcher build). These results establish code integration and automated validation, **not interactive Cocoa GUI acceptance**.

Implemented capabilities include native application/menu/window infrastructure; configurable new-frame/new-tab/reuse-current document opens; New Buffer in Mode and Change Buffer Mode; ESS-backed R source/console menus and contextual toolbar actions; explicit R session start, targeting, inspection and listing; execution-queue and output controls; Save Document As and non-destructive unsaved-document review; and keyboard/document/toolbar preferences. R Markdown, Quarto, Sweave, Shiny and remote workflows have preliminary integrations and still require separate end-to-end validation. Neither complete historical Aquamacs parity nor a production release is claimed.

**Still outstanding:** signed-app testing of Cocoa reopen/close, document safety and focus, R source-to-console execution, session targeting, native R/Quartz plotting, toolbar image/layout, persistent preferences, and optional rendering/Shiny workflows. A releasable 0.1 build also needs candidate-specific signing, notarization, Gatekeeper checks and license/source-distribution review. Earlier signed builds do not certify the current `main` tree.
